# Ship Pass 4 — Stages, Movement, Menus, Wiring: the Full Picture (opened 2026-09-04)

Owner directive (verbatim): "lets do a pass for all of the stages being improved.
The movement systems being improved. Menus, wiring, full scope, full picture."

Owner decisions (2026-09-04, asked up front):
- **Venues:** BOTH — procedural props, crowds, lighting moods and skies on every
  baked map first; CC0 prop packs where a venue clearly needs them (each download
  named with source and size before it happens).
- **Bounds:** a NAVMESH generated offline from each venue's map mesh (a recast
  library; the exact package is named before it is added). The hand-typed clamps
  in ten modes retire.
- **Menus:** a CONSISTENCY pass — one shell for every mode (pause, results,
  controls card, phone join, venue preview), every mode reachable in three taps.
  No visual redesign.
- **Scope:** focused. The anatomy layer and the physics lesson stay with pass 3.

## The picture (measured 2026-09-04)

| Layer | State |
|---|---|
| Stages | 13 baked venues (2–3 MB, one texture each, no props, one lighting) + procedural skatepark / slope / surf worlds. `gridiron` and `sand-court` are referenced in `lib/map-data.ts` with no baked file. |
| Bounds | 10 modes clamp movement with typed constants (`ARENA_HALF`, `FIELD_HALF_X`…); `venue-bounds-tests` only checks the camera box. |
| Movement | 7 movement cores (court, board, combat, field run, carrier, ground ride, air) + `gameFeel`; nothing reads the body's mass; feel is hand-tuned per mode. |
| Camera | `CameraDirector` + `cameraPresets` per mode; 0 FEL-CAM fallbacks in the last sweep; occlusion/pull-in handled, no whiskers or asymmetric damping. |
| Menus | 85 routes; hub → `/modes` (one table, `MODE_INFO`) → `/play/<mode>`; 21 game components in the shell, several 500–800 lines with their own HUD and results. |
| Wiring | Phone bridge on 22 mode keys; sessions posted by the shell; 5 analytics events in total; `game_diag` to the admin endpoint; CI on push. |

## The ladder

| Phase | Deliverable | Gate |

Sweeps run at phase boundaries; the `/loop` gauntlet reports regressions only.

## Findings log
- **4 Sep, phase 1 done.** `scripts/full-picture.mts` writes `SHIP-PASS-4-MATRIX.md`: 24 registry modes × venue spec, kit builder, baked map, movement cores, camera preset, typed clamps, phone bridge, gauntlet, play sweep, concept lock, test scripts, file size. 40 gaps. The shape of them: only 3 of 18 enabled modes stand on a baked map (karate, tennis, 3v3) although 13 maps are baked — dunk, ones, carnival and dunk duel build a kit court next to an unused Venice court; derby, penalty and golf build a kit field beside baked park, stadium and links; skate, snowboard and surf run procedural worlds beside baked park, slope and break. Seven enabled modes have no camera preset (penalty, golf, carnival, mixedcombat, dunkduel, dance, threepoint); 9 carry typed clamps (36 in all); 4 enabled modes lack a shared movement core (football, surf, onevone, mixedcombat use mode-local movement). The matrix cannot see venues mounted by a shared base (the board modes delegate to BoardRunMode), so it under-reports the board modes' kit builders.
- **4 Sep, phase 2 opened.** The raw `gridiron.glb` and `sand-court.glb` carry no textures (the pipeline refuses them as grey soup), so football and volleyball keep procedural venues and get their props in the procedural pass. First wiring: the four basketball venue specs (dunk, ones, 3v3, carnival) all point at the scanned Venice court, whose placement was tuned so the painted baseline hoop sits under the rim at world origin — the same rim position every basketball mode uses.
