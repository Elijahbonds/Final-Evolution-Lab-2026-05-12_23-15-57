# 20 gameplay and performance improvements per mode (2026-10-05)

**Owner:** "Once finished find 20 gameplay and performance improvements to make on each game mode and we'll make them."

This is a menu: the owner picks which of these get made. Nothing below has been built.

**How it was made.** Six read-only research passes, one per mode family, each told to:
- ground every item in the code with a `file:line`;
- mark anything inferred but not seen running as *(unverified)*;
- not propose what the code already does.

Nothing was profiled. "Perf" items are costs read off the code (per-frame allocations, draw calls, observers, re-renders), not measured frame times.

**Tags:**
- **S / M / L** — under an hour / a few hours / a day or more.
- **TUNED** — the item changes a feel number you signed off (speed, window, difficulty, camera). It needs your eye.

**Patterns that recur across modes.** Fixing these once in the shared code pays in many modes:
- **The HUD re-renders React every frame.** Most modes call `setHud` per frame; skipping unchanged values in `ModeHarness` fixes it everywhere.
- **Banner timers clear each other.** Each banner starts its own `setTimeout` to clear itself, so an older timer wipes a newer banner. One banner channel with an expiry fixes it.
- **`EffectsKit.burst` creates a new ParticleSystem on every call.** A small pool per kind would serve every mode.
- **Timers and scene observers run on real time.** They keep going through pause, hit-stop and slow-mo, and often after dispose.
- **Crowds are up to 8 fully animated, skinned bodies per bank.** Freezing or pausing them off-screen saves frame time.
- **Static venue meshes are rarely frozen or merged.** Freezing or merging them cuts draw calls and matrix updates.

**Already done in this pass, so not listed:**
- rival rotation and wider casts;
- the 11 retired bodies;
- the Dunk rivals' own bodies;
- the skate kick plant and wall rides;
- the wall-ride trick fix and the lip-stall cue (skate items 14 and 15 below are now done).

Modes, in order: hoops (dunk, dunkduel, onevone, threevthree, threepoint) · carnival, volleyball, tennis, golf, derby, penalty · skateboard, snowboard_slalom, surf, bigair · freerun, sprint, football, aeroaces, velocitykart · karate, karate_vs, showdown, duel, mixedcombat (+ the shared combat stack) · dance, who_scene_it, brainbrawl, tiebreak.

Paths are relative to `/home/user/Final-Evolution-Lab-2026-05-12_23-15-57/FEL-full-app/lib/babylon/` unless they start with `components/`. Three things affect several modes:
- **The harness keeps running scene observers while paused.** It calls `scene.render()` every frame even when paused, and only stops calling `update()` (`core/ModeHarness.ts:822-847`). So anything driven by `onBeforeRender`, and any `setTimeout`, carries on during a pause.
- **The HUD re-renders React every frame.** Each `setHud` call becomes a React `setHud` in the host component.
- **1v1 and 3v3 load the ball trail twice.** The second trail is never stored or disposed.
